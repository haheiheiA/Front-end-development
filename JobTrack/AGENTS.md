# JobTrack 项目开发规则

## 项目定位
JobTrack 是一个用于个人求职管理的 Web 应用。

## 技术栈
- Vue 3
- Vite
- Vue Router
- Pinia
- 原有项目依赖优先
- 不随意新增依赖

## 开发原则
- 简单 > 复杂
- 实用 > 炫技
- 稳定 > 大规模重构
- 快速迭代 > 一次性做完
- 优先复用现有代码
- 不做与当前任务无关的重构

## 修改原则
- 只修改完成任务所需的文件
- 不随意修改项目架构
- 不随意更换技术栈
- 不删除已有功能
- 不改变已经确定的页面设计
- 如果发现需要大规模修改，先说明原因

## Token 使用规则
- 优先读取与当前任务直接相关的文件，不无目的扫描整个项目。
- 修改前先判断最小修改范围，能改 1 个文件就不要改 5 个文件。
- 不为了“代码更优雅”主动重构已有代码。
- 不主动修改当前任务之外的功能。
- 不重复解释项目背景和已经完成的内容。
- 如果当前实现已经满足需求，不为了架构优化而改动。
- 优先完成可见功能，再考虑抽象、重构和优化。
- 遇到小问题时优先局部修复，不要重新设计整个模块。

## 完成任务后
- 检查代码。
- 尽可能运行项目现有检查命令。
- 只汇报：
  - 修改了什么
  - 修改了哪些文件
  - 当前功能是否完成
  - 是否存在需要用户决定的问题
- 存在未解决问题时明确指出。
- 除非用户明确要求，不输出长篇说明。
