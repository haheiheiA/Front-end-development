## 7. 技术决策

### 7.1 应用架构

- 使用 Vue 3 Composition API 和 `<script setup>`。
- 使用 Vue Router 的 `createWebHistory`。
- 使用 Pinia Setup Store 管理岗位数据。
- 使用单一 `useJobStore` 作为岗位数据源。
- 使用 `DefaultLayout` 和 `AppLayout` 分离默认布局与应用外壳。

### 7.2 样式方案

- 使用 Tailwind CSS 4。
- 在 `main.css` 中通过 `@theme` 定义颜色、圆角和阴影令牌。
- 不使用 UI 组件库作为核心 UI 实现。
- 保持现有页面设计，不为“看起来更专业”进行无关重写。

### 7.3 数据模型

- 招聘状态和来源使用联合类型，避免散落字符串。
- 薪资使用结构化数值和 `month` / `year` 单位，展示时统一格式化。
- 时间字段使用 ISO 8601 字符串。
- 当前使用 Mock 数据，仅用于验证前端流程。

### 7.4 暂不引入

- 后端服务。
- 用户系统和权限。
- 额外 UI 框架或状态库。
- OpenLayers。当前 `package.json` 未安装该依赖，也没有地图功能；旧状态文档中的相关表述不属于当前实现。
- 与核心 Job 流程无关的大型功能。

## 8. 开发原则

- 简单优先于复杂。
- 实用优先于炫技。
- 稳定优先于大规模重构。
- 快速迭代优先于一次性完成。
- 优先复用现有代码与依赖。
- 只修改完成任务所需的文件。
- 不改变已经确定的页面设计。
- 不删除已有功能。
- 不重复创建 Job 数据源。
- Dashboard 和列表应继续消费统一 Job Store。
- 如果任务需要大规模修改，先说明原因，不要直接重构。
- 每完成一个明确阶段，运行现有检查命令并更新本文件。
