## 2. 已完成内容

### 2.1 工程基础

- Vue 3、TypeScript 和 Vite 项目配置可用。
- `main.ts` 已注册 Pinia、Router 并加载全局样式。
- Tailwind CSS 4 通过 `@tailwindcss/vite` 接入。
- 已配置 `dev`、`build`、`preview` 三个 npm 脚本。
- `npm run build` 会先执行 `vue-tsc -b`，再执行 Vite 生产构建。

### 2.2 路由

已配置以下路由：

- `/` 重定向到 `/dashboard`。
- `/dashboard`：概览。
- `/jobs`：岗位列表。
- `/progress`：求职进度。
- `/jobs/new`：添加岗位。
- `/jobs/:id`：岗位详情。
- `/jobs/:id/edit`：编辑岗位。

路由标题通过 `meta.title` 提供给 `AppHeader`。当前没有 404 路由和路由级懒加载。

`src/stores/job.ts` 已提供：

- `jobs`
- `getJobById`
- `addJob`
- `updateJob`
- `deleteJob`

Dashboard、求职进度、列表页、详情页以及新增 / 编辑 / 删除 / 状态快捷修改都已消费统一 Store；Job 支持可选的 applicationRecords、interviewRecords、offer 和 contacts 字段，旧数据按空值或空数组兼容。

求职进度页的求职漏斗只从 `jobs` 派生，不新增 Store、数据字段或独立统计副本。近期求职数据、最近 7 天活动趋势和最近动态也只从 `jobs`、`applicationRecords` 和 `interviewRecords` 派生，不保存统计结果。

## 7. 技术决策

### 7.1 应用架构

- 使用 Vue 3 Composition API 和 `<script setup>`。
- 使用 Vue Router 的 `createWebHistory`。
- 使用 Pinia Setup Store 管理岗位数据。
- 使用单一 `useJobStore` 作为岗位数据源。
- 使用 `DefaultLayout` 和 `AppLayout` 分离默认布局与应用外壳。

### 7.2 样式方案

- 使用 Tailwind CSS 4。
- 在 `main.css` 中通过 `@theme` 定义颜色、圆角和阴影令牌。
- 不使用 UI 组件库作为核心 UI 实现。
- 保持现有页面设计，不为“看起来更专业”进行无关重写。

### 7.3 数据模型

- 招聘状态和来源使用联合类型，避免散落字符串。
- 薪资使用结构化数值和 `month` / `year` 单位，展示时统一格式化。
- 时间字段使用 ISO 8601 字符串。
- 首次访问使用 Mock 数据，之后由 LocalStorage 持久化；当前没有后端数据源。

### 7.4 暂不引入

- 后端服务。
- 用户系统和权限。
- 额外 UI 框架或状态库。
- OpenLayers。当前 `package.json` 未安装该依赖，也没有地图功能；旧状态文档中的相关表述不属于当前实现。
- 与核心 Job 流程无关的大型功能。

## 8. 开发原则

- 简单优先于复杂。
- 实用优先于炫技。
- 稳定优先于大规模重构。
- 快速迭代优先于一次性完成。
- 优先复用现有代码与依赖。
- 只修改完成任务所需的文件。
- 不改变已经确定的页面设计。
- 不删除已有功能。
- 不重复创建 Job 数据源。
- Dashboard 和列表应继续消费统一 Job Store。
- 如果任务需要大规模修改，先说明原因，不要直接重构。
- 每完成一个明确阶段，运行现有检查命令并更新本文件。

## 9. 新会话建议工作方式

开始开发前：

1. 阅读 `AGENTS.md`。
2. 阅读本文件并确认当前阶段。
3. 阅读 `README.md` 对外描述是否仍与实现一致。

2. 检查是否修改了无关文件。
3. 更新“已完成内容”“当前正在进行的内容”“已知问题”和验证记录。
4. 不要把规划中的功能写成已完成功能。
